# Domain documentation

This repository has one context. Before design or terminology changes, read
[CONTEXT.md](../../CONTEXT.md). Use its terms in issues, code, and reports.
Keep the glossary free of implementation details.

If `docs/adr/` exists, read decisions that affect the current work. Proceed
if it does not exist. Add an architecture decision only for a significant
trade-off that is hard to reverse and would otherwise be hard to explain.

Use [the runtime contract](../runtime-contract.md) for implementation
requirements. If a proposal conflicts with a recorded decision, state the
conflict before changing it.
